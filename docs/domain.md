# 东盟需求撮合枢纽领域约定

## 基本原则

- **事件溯源**：所有状态变更先序列化为不可变事件，追加写入事件日志（JSONL，fsync）；
  服务重启时按序重放，还原每轮推荐与洽谈状态。审计记录只追加、不覆盖。
- **事件时间与接收时间分离**：事件载荷携带业务发生时刻（`at`），事件序号（`seq`）表示接收顺序。
- **身份由调用方提供稳定标识**：`buyer_ref` / `supplier_id` 由外部实名体系给出，本服务不做身份签发。

## 核心领域规则

### 1. 实名资格与公开需求分离
- 采购方实名信息（法人名称、联系方式、证照）存放在独立的身份保险库（`buyer.registered` 事件），
  默认不随需求公开。
- 公开需求与撮合结果只出现匿名代号 `buyer_ref`；实名信息仅 `staff` 角色可读取。

### 2. 需求修订按轮次冻结
- 需求有版本化轮次（round）。开放轮次内修订递增 `revision`；
- 轮次冻结后再次修订自动开启新一轮，历史轮次不可变；
- 生成推荐时若轮次未冻结会先冻结，推荐只基于冻结快照。

### 3. 供应商响应：防重复 + 联合方案
- 同一需求轮次内，牵头供应商不能重复响应；
- 同一供应商不能同时出现在两个联合方案中；
- 联合方案聚合全部成员的原产地、语言、能力标签与交付窗口，牵头方必须是成员；
- 响应提交支持 `Idempotency-Key` 幂等重放；支持报价修订（revision 递增）与退出。

### 4. 可解释匹配
- 硬约束（不满足即淘汰，给出机器可读原因）：行业、国家准入原产地、交付窗口交集、
  语言、利益冲突（主办方排除名单 + 供应商自报）、必备能力、供应商状态、报价币种与预算上限。
- 通过硬约束后按固定分项评分（行业 40 / 国家规则 20 / 语言 20 / 交付窗口 20），
  评分不与任何竞争报价比较。
- 报价仅与**该需求预算**比较，任何一方的解释都不包含其他候选的报价。

### 5. 人工调整必须留痕
- 支持人工纳入、排除、调整名次；必须记录操作人与原因；
- 每次调整保存调整前/后的名次；调整不可删除，只能再追加调整；
- 本轮一旦产生预算承诺，推荐锁定，不再允许人工调整。

### 6. 候选退出只做增量重算
- 候选退出后保留其历史评估与各代推荐快照，仅从当前有效名次中移除并重排队形；
- 重算事件记录触发方与前后名次；没有生成过推荐的轮次不受影响。

### 7. 预算的预留与承诺
- 开启洽谈即按报价（或指定额度）预留预算；洽谈拒绝/关闭释放预留；
- 确认时预留转为承诺；全程持有事件存储全局锁，并发确认不可能让同一预算重复承诺；
- 确认接口幂等（`Idempotency-Key`），重复请求回放同一结果，不二次扣款。

### 8. 重启恢复
- 重放事件即可还原：需求轮次、推荐各代快照、人工调整、增量重算记录、
  洽谈状态机、预算预留/承诺台账与幂等表。

## 角色与可见性

| 内容 | staff | buyer | supplier |
| --- | --- | --- | --- |
| 采购方实名信息 | 可见 | 否 | 否 |
| 推荐名次与评分原因 | 可见 | 可见 | 仅自己的解释 |
| 候选报价 | 可见 | 可见 | 仅自己的报价 + 预算上限 |
| 预算台账 | 可见 | 可见 | 否 |
